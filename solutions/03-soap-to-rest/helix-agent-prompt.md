# Agent-mode prompt — serve a SOAP backend as REST/JSON

Paste this to the Helix Agent as one message, replacing the `<<...>>` values.
Bring your own SOAP endpoint and the handler path it answers on.

**Deploy and check after step 1, before step 2.** A mediation failure and an auth
failure look alike from the outside, and splitting at that seam tells you which
one broke. Why the prompt is worded this way, what the agent decides on its own,
and what to check before you trust it are in the
[README](README.md#build-it-with-the-helix-agent).

## Prompt

```text
Step 1:
Create a REST API called "<<Partner Locations API>>" in the <<test>> environment,
fronting a SOAP backend at <<SOAP_UPSTREAM_URL>>. One route — POST /locations —
proxying to the upstream path <<SOAP_HANDLER_PATH>>. Partners send and receive
JSON; the backend keeps speaking XML, and neither side changes to make that work.
Tell me anything in the JSON shape I wouldn't have designed by hand, and ask me
rather than guessing the handler path or the request field names.

Step 2:
Add one more route: POST /oauth/token, so an app can trade its client credentials
for a token generated by the gateway. Update /locations to validate the token
generated by this endpoint, and to reject an unauthenticated call before it does
any work on the body.

Step 3:
Create a developer "<<Partner Integrations>>", a corresponding product and an app
to work with the above API. Give me the app's client id and secret, then curl
commands showing: no token → 401; client credentials → 200 with an access_token;
that token → 200 with a JSON body that contains no angle brackets.
```
